# 감독 레벨 (Supervision Level) — 자율성 게이트 정책 (단일 진실 원천)

> 사용자가 "어느 단위로 확인하며 갈지"를 레벨로 선언하면, 모든 작업·에이전트·커맨드는 **그 레벨의 게이트만** 적용한다.
> 목적: 파일 단위 확인(페어)과 목표 위임(지시자)을 하나의 축으로 통합 — 확인을 없애는 게 아니라 **확인 단위를 승격**하는 것.

## 레벨 정의

| 레벨 | 이름 | 자율 단위 | 게이트 (사용자 개입 지점) | 용도 |
|:--:|---|---|---|---|
| **L0** | 페어 모드 | 파일 1개 | 매 파일 diff 확인 | 민감 코드, 프로덕션 핫픽스, 학습 목적 |
| **L1** | 태스크 모드 | Task 1개 | Task 완료 시 diff+검증 결과 보고, 커밋 승인 | 신뢰 형성 구간, 복잡한 리팩토링 |
| **L2** | 스프린트 모드 | Sprint 전체 | ① sprint{N}.md 계획 승인 ② 완료 리뷰 (실행 가능 상태 + 테스트 가이드) | **지시자 모드 표준** — 명세가 명확한 기능 개발 |
| **L3** | 오토파일럿 | Phase (연속 스프린트) | ① phase{N}.md 승인 ② Phase 통합 리뷰 | 자리 비울 때, 신뢰 축적 후 |

## 현재 기본 레벨

- **L1** (레벨 미선언 세션의 기본값. L2 신뢰가 쌓이면 사용자가 이 줄을 직접 상향)

## 발동 방법

- 세션 중 선언: "L2로", "스프린트 모드로 진행해", "이번 작업은 L0으로"
- 작업 요청에 병기: "L2로 sprint 3 돌려줘"
- **위임 신호는 레벨 상향으로 해석**: "권한 다 OK"/"자리 비울게"/"묻지 말고" = 해당 작업 동안 L2~L3 ([`feedback_blanket_authorization`](../memory/feedback_blanket_authorization.md) 연동). 작업 종료 시 기본 레벨로 복귀.

## 레벨 불변 원칙 (어느 레벨에서도 유지 — 상향 불가 게이트)

1. **git push / 메인 브랜치 병합 / 배포 / 인증정보 설정** → 항상 사용자 게이트
2. **Critical 보안 이슈 발견** → 즉시 중단 + 보고 (다음 단계로 미루지 않음)
3. **완료의 정의**: 실행 가능 상태 + 테스트 가이드 제공 — 사용자의 "눈으로 확인"은 게이트에서 이루어진다 (`verification-before-completion` 스킬)
4. **스코프 준수**: 명세(sprint{N}.md 등)에 없는 스코프 변경이 필요해지면 중단 + 보고 — 자율 확대 ≠ 재량 확대
5. **검증 3회 실패** → 중단 + 시도 내역 보고

## 레벨별 실무 게이트 매핑

| 동작 | L0 | L1 | L2 | L3 |
|---|:--:|:--:|:--:|:--:|
| 파일 수정 후 확인 대기 | ✅ | ❌ | ❌ | ❌ |
| 커밋 | 승인 후 | 승인 후 | 자동 (작업 브랜치 내) | 자동 |
| Phase(Task 그룹) 체크포인트 | 확인 | 확인 | 보고만, 계속 진행 | 보고만 |
| 병렬 에이전트 실행 | 제안+승인 | 제안+승인 | 명세에 있으면 자동 | 자동 |
| 스프린트 완료 리뷰 | ✅ | ✅ | ✅ (핵심 게이트) | 보고 후 자동 통과 |
| PR 검토 (sprint-close → sprint-review 사이) | ✅ | ✅ | ✅ | 보고 후 자동 통과 |
| Phase(대단위) 리뷰 | ✅ | ✅ | ✅ | ✅ (핵심 게이트) |
| 독립 리뷰 서브에이전트 (구현자≠검증자) | 선택 | 선택 | **필수** (스프린트 말미) | **필수** |

> L2+ 에서 파일 단위 확인을 생략하는 대신, **검토 가능성은 구조로 보장**한다: Task별 커밋(되돌리기 쉬움) + 스프린트 완료 리포트(무엇을 스스로 고쳤는지 포함) + 독립 리뷰.
