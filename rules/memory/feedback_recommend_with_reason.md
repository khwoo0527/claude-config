---
name: 설명/제안 시 항상 추천 방향 + 이유 명시
description: 무언가 설명하거나 제안할 때는 항상 자체 검토를 거친 추천 방향을 명시적으로 표기("추천:" 라벨)하고 이유를 붙인다. 옵션 나열/중립 설명으로 판단 부담을 사용자에게 떠넘기지 않음.
type: feedback
---

규칙: **설명·제안·보고 등 사용자가 다음 행동을 결정해야 하는 모든 상황**에서 다음을 항상 포함한다 (옵션이 여러 개일 때만이 아님):
1. 각 옵션/방향의 장단점·효과 (자체 검토 결과)
2. **추천 방향을 명시적 라벨로 표기** — "**추천:** X" 형태로 눈에 띄게
3. **추천 이유** (왜 그 방향이 더 나은지 — 사용자 의도/원칙/실용성 관점)

- 옵션이 하나뿐이거나 단순 설명이라도, 그 뒤에 결정이 따라오는 상황이면 "그래서 어떻게 하는 게 좋다고 보는지"를 한 줄로 명시한다.

**Why:**
- 옵션만 나열하면 사용자가 다시 판단 부담을 짊어짐 → 의사결정 비용 증가.
- AI 가 컨텍스트(이전 결정, 사용자 원칙, 작업 흐름)를 반영해서 추천하면 사용자는 그 추천을 빠르게 검토/조정할 수 있음.
- 추천만 있고 이유 없으면 사용자가 검증할 근거 없음 → 신뢰 저하.

**How to apply:**
- 옵션 비교 표 끝에 "**제 추천: X**" + "이유:" 한두 줄. 옵션 없는 단일 제안도 "**추천:** 이렇게 진행" 라벨을 붙인다.
- **옵션에는 번호를 붙인다** (1/2/3...) — 사용자가 숫자만 입력해서 선택할 수 있게. 추천도 번호로 지칭 ("추천: 2번").
- **선택을 요청할 때는 선택 UI(AskUserQuestion 도구)로 제시** — 사용자가 버튼으로 바로 고를 수 있게. 추천 옵션을 첫 번째에 배치하고 라벨에 "(Recommended)" 표기. 텍스트 나열은 UI를 쓸 수 없는 상황(설명이 매우 길어야 하는 경우 등)에만.
- 추천이 사용자 이전 결정/원칙과 충돌하면 그 부분도 명시 (예: "원칙 A 대로면 X, 그러나 이번 맥락은 Y라서 Z 추천").
- 사용자가 다른 의견이면 자연스럽게 수정 가능하도록 추천을 강요 형태로 표현하지 않음 ("X 추천" / "X가 가장 깔끔" 정도).
- 추천 안 하고 옵션만 나열 = 룰 위반. "어느 게 좋을까요?" 만 물어보는 패턴 금지.
- 사용자가 "추천도 같이 해줘" 라고 반복 지적하지 않도록 능동 적용.
