rules/tech/{tech}.md 를 객관적으로 채점하는 커맨드 — 기계 실측 + 독립 채점 에이전트 + README 반영까지 한 절차로.

> **왜 필요한가**: 작성자 자신이 채점하면 매몰 편향으로 점수가 왜곡된다.
> 실증 사례 (2026-07-03 검토): 자기 채점 vs 독립 실측이 4개 파일 전부 불일치 (TS 72 주장 → 실측 55 상한 / C# 40 표기 → 실측 85).
> 원인 = ① 작성자 단독 채점 ② 채점이 "선택" ③ README 반영 루프 부재. 이 커맨드가 세 가지를 모두 구조로 해결한다.

## 인수

`$ARGUMENTS`: 채점 대상 기술명 (예: `csharp`, `typescript`) 또는 `all` (전체 재채점).

## 실행 절차

### 1단계: 기계 실측 (판단 개입 0 — 숫자 산출)

대상 파일에 대해 다음을 **실제 명령으로 카운트**한다 (회상/눈대중 금지):

| 지표 | 측정 방법 | 관련 카테고리 |
|------|----------|:---:|
| 코드 블록 수 | ``` 펜스 쌍 카운트 | B |
| Good/Bad 쌍 수 | ✅/❌ (또는 Good:/Bad:) 대비 블록 카운트 | B |
| 안티패턴 테이블 항목 수 | 안티패턴 섹션의 표 행 카운트 | C |
| 실전 함정 수 + 4요소 완비 수 | 함정 섹션 행 카운트 + `증상|원인|해결|오답` 4컬럼 완비 검사 | D |
| 검증 체크리스트 수 | `- [ ]` 블록 그룹 카운트 | E |
| 필수 섹션 존재 여부 | rules-guide 템플릿 구조의 필수 섹션 헤더 grep | A + 상한선 |
| 프로젝트 종속 용어 | 프로젝트 고유명사 grep (0건이어야 함) | 상한선 |
| 네이밍 테이블 행 수 | 네이밍 컨벤션 섹션 표 행 카운트 | A/F |

실측 결과를 표로 정리한다. **이 숫자들이 채점의 근거 데이터** — 다음 단계 에이전트에게 그대로 전달.

### 2단계: 독립 채점 에이전트 (질적 판정)

**작성자(현재 세션)가 아닌 별도 서브에이전트**를 스폰하여 채점시킨다:

```
Agent(general-purpose) prompt 표준:
"너는 rules 파일의 독립 채점자다. 이 파일의 작성 맥락은 모른다.
 1) .claude/rules/workflow/rules-guide.md 의 품질 평가 체계(카테고리 A~F, 깊이 등급,
    자동 상한선, Level 게이트)를 읽고,
 2) 대상 파일 {rules/tech/{tech}.md} 를 정독한 뒤,
 3) 아래 기계 실측치를 근거 데이터로 사용하여: {1단계 실측 표}
 4) 깊이 등급(피상 30%/구체 70%/실전 100%)과 카테고리별 점수를 판정하고
    채점 워크시트 형식으로 결과를 산출하라.
 관대하게 주지 마라 — 상한선과 Level 게이트를 기계적으로 적용하라."
```

- 에이전트는 **깊이 등급 판정** (실패 결과가 구체적인가, 함정이 실전 검증인가) 같은 질적 영역을 담당.
- 정량 수치는 1단계 실측치를 그대로 사용 — 에이전트가 다시 세지 않음 (이중 오차 방지).

### 3단계: 판정 확정 + 보고

1. 에이전트 워크시트 결과를 받아 상한선/게이트 적용을 재확인한다 (min 연산 검증).
2. 사용자에게 보고:
   ```
   📊 {tech}.md 객관 채점 결과
   | 카테고리 | 점수 | 근거 (실측치) |
   ...
   상한선: {적용 여부 + 사유} / 최종: {점수}점 = Level {N}
   이전 README 표기: {점수} → 변동 {±N}
   부족 카테고리 보강 제안: {구체 항목}
   ```

### 4단계: README 반영 (집행 루프)

- 점수가 README 표와 다르면 **즉시 README 기술 규칙 표를 갱신**한다 (채점 일자 병기).
- 이 단계를 건너뛰지 않는다 — 표가 낡으면 보강 우선순위 판단이 뒤집힌다 (C# 40 표기 사례).

## 호출 시점 (필수)

- rules/tech/{tech}.md **신규 작성 직후** (배포 판정 — 60점 미만이면 배포 금지)
- **대폭 수정 후** (섹션 추가/재작성 수준)
- 정기: `/ReviewClaudeConfig` 전체 점검 시 점수 스테일 여부 확인

> 소소한 노하우 1~2줄 누적(tech-knowledge 정책)은 재채점 불필요 — 대폭 수정만 트리거.

## 동작 원칙

- **작성자 단독 채점 금지** — 질적 판정은 반드시 독립 에이전트.
- **실측 우선** — 셀 수 있는 것은 전부 명령으로 센다.
- **관대 금지** — 상한선/게이트는 기계적으로 적용. "아깝다"는 채점 사유가 아님.
- 채점 결과가 이전과 크게 다르면 (±15점 이상) 원인 한 줄 보고 (보강했는가 vs 이전 채점이 부풀려졌는가).
