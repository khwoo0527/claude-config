# Simplify — 커밋 전 코드 정리

> **한 줄 정의**: 동작은 그대로, 코드만 시니어가 쓴 것처럼. 커밋 직전에 실행하는 마지막 다듬기 단계.
> 리팩토링(구조 변경)이 아니라 **정리(cleanup)**다 — 이 구분이 이 스킬의 전부다.

---

## 절대 원칙 (하나라도 어기면 simplify가 아님)

1. **동작 보존** — 기능, 공개 API 시그니처, 입출력, 부수효과를 바꾸지 않는다. 바꾸고 싶은 게 보이면 정리가 아니라 별도 Task/백로그로 분리한다.
2. **스코프 한정** — 이번 Task에서 생성/수정한 파일만. "겸사겸사" 옆 파일 정리 금지 (`git diff --name-only`가 스코프의 진실).
3. **rules가 기준** — 정리 기준은 취향이 아니라 `.claude/rules/tech/{tech}.md`. 정리 전에 해당 rules의 네이밍/포맷팅/안티패턴 섹션을 다시 읽는다.
4. **검증으로 마무리** — 정리 후 빌드+테스트 재실행 통과까지가 이 스킬의 범위. 통과 전에는 완료가 아니다.

---

## 실행 절차

### 1단계: 스코프 확정
```bash
git diff --name-only   # 이번 Task에서 건드린 파일 목록 = 정리 대상 전체
```

### 2단계: 정리 체크리스트 적용 (파일별)

| # | 점검 | 기준 |
|---|------|------|
| 1 | 죽은 코드 | 미사용 import/변수/함수, 주석 처리된 옛 코드, 디버그 출력(console.log/Debug.WriteLine) 제거 |
| 2 | 네이밍 | rules/tech 네이밍 테이블과 대조 — 임시 이름(temp, data2, foo) 잔존 여부 |
| 3 | 매직값 | 인라인 리터럴/매직넘버 → 상수 분리 (rules의 하드코딩 금지 규칙) |
| 4 | 중복 | 이번 변경 안에서 3회+ 반복된 로직 → 추출. **2회는 그대로 둔다** (성급한 추상화 금지) |
| 5 | 중첩 | 3단 이상 중첩 → early return / guard clause로 평탄화 |
| 6 | 주석 | 코드를 반복 설명하는 주석 제거 — "왜"를 설명하는 주석만 유지 |
| 7 | 방어 과잉 | 도달 불가능한 null 체크, 의미 없는 try-catch(삼키기) 제거 — 에러는 경계에서만 |
| 8 | 임시 잔재 | TODO 없는 임시 코드, 실험용 분기, 사용 안 하는 매개변수 정리 |

### 3단계: 재검증
- CLAUDE.md의 빌드 명령 실행 → 통과 확인
- 테스트 명령 있으면 실행 → 통과 확인
- 실패 시: 정리 중 동작을 건드린 것 — 해당 정리를 되돌리고 원인 파악 (땜빵 수정 금지)

### 4단계: 결과 요약 (1~3줄)
```
🧹 simplify: {파일 수}개 파일 — 미사용 import 4건 제거, {이름}→{이름} 개명 2건, 매직넘버 3건 상수화. 빌드/테스트 통과.
```
정리할 것이 없었으면 "정리 대상 없음 — 통과"라고 명시한다 (건너뛴 것과 구분).

## Good / Bad

```csharp
// ❌ Bad simplify — 정리를 빙자한 기능 변경
- public List<Item> GetItems() { ... }
+ public IEnumerable<Item> GetItemsAsync() { ... }   // 시그니처 변경 = 리팩토링, 스킬 범위 밖

// ✅ Good simplify — 동작 동일, 가독성만 개선
- var r = items.Where(x => x.Type == 1).ToList();
+ var activeItems = items.Where(x => x.Type == ItemType.Active).ToList();
```

```
❌ Bad: "이 파일 보다 보니 옆 클래스도 지저분해서 같이 정리했습니다" (스코프 위반)
✅ Good: "옆 클래스에도 같은 패턴이 보입니다 — 백로그에 기록해둘까요?" (분리 제안)
```

---

## 에러 처리

- 정리 후 빌드/테스트 실패 → 마지막 정리 항목부터 역순으로 되돌리며 원인 특정. 원인 항목은 정리 포기 + 사유 보고.
- rules/tech/{tech}.md 부재 → 언어 표준 컨벤션으로만 최소 정리 (1, 5, 8번 항목) + rules 생성 제안.
